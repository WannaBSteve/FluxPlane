# 前端选型与产品设计

更新：2026-11-09。精美、可交互的前端是正式交付要求，与后端同步推进。

## 1. 推荐方案

以 **satnaing/shadcn-admin** 的应用布局和组件为基础，结合 **React Flow** 构建特征依赖与任务 DAG，使用已有的 **Recharts** 组件绘制运行指标。

当前技术组合：React + TypeScript + Vite + Tailwind CSS + shadcn/ui 组件 + React Flow + Recharts。路由、数据缓存与表格能力仍以轻量本地实现为主。

它适合独立 FastAPI 后端，可以构建静态前端产物。原仓库明确说明自己是可复用 UI 项目，而非精简 starter；因此接入方式是抽取布局与组件、替换业务模块，不将原演示页面视为已完成的平台功能。

已从固定提交抽取主题和 UI 组件，保留 MIT 许可证，完成与真实 API 连接的六个控制台视图。`npm run build` 已通过；浏览器交互、桌面与窄屏布局、主题切换、SQL 查询及 SSE 触发的任务状态更新已验证。事件流断线后从最后收到的事件继续，另以低频快照刷新兜底。

## 3. 专用组件

| 组件 | 用途 | 使用范围 |

React Flow 的交互画布不自动解决排版；首版同时实现按依赖层级的自动布局，保证节点不重叠、边可追踪。大图默认展示关联子图，支持聚焦上游和下游。

## 4. 视觉方向

产品应呈现为专业的数据系统控制台。优先级是清晰的层次、统一的密度和可信的运行状态。

- 默认浅色：白色内容面板、浅灰背景、细边框，蓝色作为主强调色；提供完整深色主题。
- 固定侧栏、紧凑顶栏、清晰面包屑，页面操作保持相同位置。
- 控件圆角和间距使用统一 token；主内容字号 14px，辅助信息不低于 12px，减少装饰性大卡片。
- 数值使用等宽数字；中文优先系统字体，避免依赖远程字体服务。
- 状态同时使用文字、图标和颜色，不能仅靠红绿区分。
- 动效服务于展开、定位和状态变化；尊重减少动效偏好。
- 常用操作支持键盘，全局搜索可检索数据集、特征和任务。
- 主要验证 1440px 桌面和 1280px 笔记本；窄屏折叠侧栏，表格保留列管理及横向滚动。

前端的核心辨识度来自三个真实视图：**多源数据目录、持续更新的特征依赖图、可解释的任务调度视图**。

## 5. 页面与具体内容

| 页面 | 主视图 | 详情与操作 |
|---|---|---|
| 系统总览 | 数据新鲜度、运行任务、队列与资源趋势 | 最近更新、异常任务、关键入口 |
| 数据目录 | 来源/数据集列表与预览 | schema、画像、版本、同步记录、依赖 |
| 特征中心 | 特征列表 + 依赖图切换 | 定义、时间窗口、更新策略、快照与刷新 |
| 任务中心 | 队列、运行列表、单次 DAG | 等待原因、资源请求、重试、取消与日志 |
| 分析工作台 | SQL 编辑区和结果表 | 数据结构浏览、来源与版本、执行状态 |
| 版本与存储 | 版本时间线与产物占用 | 版本比较、回退、保留与回收状态 |

“动态”必须能解释：任务详情显示依赖未就绪、资源不足或等待调度等真实原因；特征页面显示上游变化、窗口到期或定义变更等刷新原因。

主页面显示业务可理解的信息，线程、租约代次、重试栈等放在可展开的运行详情中。

## 6. 前端与后端合同

1. 通过 OpenAPI 生成 TypeScript 类型；枚举和字段不在两端各自维护。
2. REST 查询确定状态，SSE 触发增量刷新；断线续传或重新获取快照，不能依赖浏览器内计时模拟任务进度。
3. 分页、筛选、排序写入 URL，刷新和分享链接可恢复视图。
4. 表格、图表和依赖图读取同一实体状态；失败、空数据、加载和无权限都有专门表现。
5. 取消、刷新与回退等操作显示后端确认结果；前端不能自行判断发布已成功。
6. 仅在开发环境使用 fixture，显式标注演示模式；最终演示接真实 API 和 worker。
7. 删除原模板的假认证、赞助入口和未使用模块，使用平台认证与授权。

## 7. 实施安排与完成标准

- **M0**：固定基础版本，抽取应用布局，清理无关模块，确定设计 token 和路由。
- **M1**：先实现数据目录与分析工作台，接入真实多源分析闭环。
- **M2**：任务列表、DAG、资源状态、取消与恢复反馈。
- **M3**：特征依赖、刷新、版本比较与新鲜度状态。
- **M4**：总览、存储与后台优化视图。
- **M5**：浅/深色主题、键盘操作、响应式、错误状态和端到端验收。

完成标准包括：核心场景全程通过界面完成；表格与 DAG 无遮挡；主要宽度下布局稳定；SSE 重连后状态正确；失败和取消反馈明确；无旧项目或原模板的产品品牌残留。保留必要第三方版权说明。

当前已完成可运行的首版页面、真实 API 接线、SSE 驱动刷新、任务预留容量与 worker 资源观测视图、持久执行计划及任务 DAG 展示；“版本与存储”页显示查询物化状态和复用次数。控制台读取服务端角色并按同一权限显示操作。读取模型和来源类型由 OpenAPI 生成，`npm run check:api` 检查契约同步。全局搜索可定位数据集、特征和最近任务，页面与筛选条件可从 URL 恢复。真实浏览器已验证字段画像、数据集选择与查询结果翻页；390px 宽度下没有页面横向溢出。更完整的资源趋势仍按 M0–M5 继续实施。

## 8. README 的系统架构表达

架构围绕分析、数据更新与持久状态组织：

```text
应用界面                 数据目录 / 特征中心 / 任务中心 / 分析工作台
服务接口                 REST API / SSE / CLI
任务协调                 依赖规划 / 调度 / 资源准入 / 更新 / 发布 / 恢复
执行运行时               SQL / Python / 文档 / 后台维护
数据适配器               数据库 / 文件 / HTTP / 文档 / 产物存储
持久状态与外部资源       目录 / 任务 / 版本 / 数据快照 / 源系统
```

访问控制与运行观测贯穿各模块。
